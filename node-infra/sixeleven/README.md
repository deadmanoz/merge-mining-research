# SixEleven node (Dockerised)

This workspace runs the official SixEleven image for historical
Bitcoin-parent AuxPoW recovery. The image is pinned to the linux/amd64
manifest digest behind `611project/611coin:edge`, rather than following the
mutable tag.

The upstream image prints `611.conf`, including its RPC password, when a
misnamed entrypoint variable is unset. `container-entrypoint.sh` requires the
config generated by `just init`, suppresses that unsafe output, and then
delegates to the image's original entrypoint.

| Parameter | Value |
|---|---|
| P2P magic | `f9 be b6 11` |
| P2P port | 8661 |
| RPC port | 8663, bound to host loopback |
| AuxPoW chain ID | 1 |
| AuxPoW activation | child height 19,200 |
| Observed tip | 999,406 on 2026-07-10 |

The chain ID and activation correct older catalogue values of chain ID 0 and
activation near genesis. `dnsseed.611.to` returned three reachable peers at
height 999,406 on 2026-07-10. The verified `peers.list` adds five peers that
were reachable at that height; the completed recovery node held six live
connections.

## Usage

```bash
just init
just pull
just up
just logs
just height
just peers
just status
just down
```

The default data directory is `./data`. Put it on another disk without editing
the compose file:

```bash
export SIXELEVEN_DATA_DIR='<chain-data-dir>/sixeleven'
just init
just up
```

Provision about 5 GB initially. The completed height-999,406 datadir measured
2.4 GB on 2026-07-10.

The legacy RPC response does not expose the full AuxPoW proof, so recovery
parses the synced datadir's numbered `blkNNNN.dat` files. `blkindex.dat` is not
a numbered block file and is deliberately excluded:

```bash
just extract sixeleven_auxpow_candidates.raw.csv
```

The raw extractor leaves child height blank because disk order is not consensus
order. Resolve exact child heights through the synced legacy SixEleven RPC
before Bitcoin classification:

```bash
source ../../.venv/bin/activate
python ../../scripts/prep/normalize_auxpow_child_heights.py \
  --chain sixeleven \
  --input sixeleven_auxpow_candidates.raw.csv \
  --output sixeleven_auxpow_candidates.heights.csv \
  --rpc-conf "${SIXELEVEN_DATA_DIR:-./data}/611.conf"
```

The resolver uses legacy `getblock <hash>`, validates child hash, version,
timestamp, confirmations, canonical `getblockhash(height)` identity, and the
height-19,200 activation boundary. Feed the `.heights.csv` file to the Bitcoin
parent classifier, never the `.raw.csv` file.

## Completed recovery

The 2026-07-10 run reached height 999,406 with six peers and then froze the
datadir for extraction. The complete pass scanned 999,407 blocks: 969,317
AuxPoW, 30,090 non-AuxPoW, and no parse or chain-ID errors. Of 80,364 parent
headers meeting their claimed Bitcoin target, Bitcoin Core classified 7 as
canonical, 0 as stale, and 80,357 as unknown. The subsequent BTC-relevance
pass found 0 strict and 0 weak orphans; every unknown candidate failed the
Bitcoin epoch-nBits consistency gates.

The compact canonical evidence is
`results/monitor-evidence/sixeleven_monitor_evidence.csv`. The header-only
`data/validated-stales/sixeleven_validated_stales.csv` preserves the zero-stale outcome. The raw
and normalized 80,364-row candidates remain in the private archive.
